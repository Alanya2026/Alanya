Ajout à un groupe — Rester ou quitter

Quand Alice ajoute Marc à un groupe, Marc voit une bannière discrète en haut du fil (style WhatsApp, au-dessus de tous les messages — pas de modal). Les autres membres voient le message système classique dans le fil. Si Marc choisit Rester, POST /ack-join clear pendingJoinMsgID (sync multi-appareil). S'il choisit Quitter, on appelle POST /conversations/:id/leave. Le réglage admin masquer l'historique (défaut OFF) décide si Marc voit les messages antérieurs à son ajout.

Marc tape Rester POST /ack-join → pendingJoinMsgID = NULL → bannière disparait sur tous ses appareils via conversation:updated. Le sys-msg reste dans le fil.

Autres membres Sys-msg classique « Alice a ajouté Marc », jamais la bannière
Multi-appareil pendingJoinMsgID serveur : Rester sur un appareil retire la bannière partout après sync
Historique masqué (ON) À l'ajout : historyCutoffAt = NOW(). GET /messages et /messages/sync filtrés. Défaut OFF = historique complet.
Ré-ajout après exclusion Re-afficher la bannière (nouveau member_added + nouveau pending) ; nouveau cutoff selon le réglage courant
Créateur du groupe Pas de bannière (pas de pending pour le créateur)
Invités à la création Même flux qu'un addParticipants : member_added + pendingJoinMsgID + bannière

Style WhatsApp. Pas d'icône, pas de carte ombrée, pas de gros boutons pleins. Texte gris 12,5 px centré, actions en liens texte (Rester · Quitter). Fond surfaceMuted, fine bordure basse.

Placement fixe. La bannière est un sibling du fil scrollable, pas un item dedans : elle reste visible en haut pendant que Marc scroll l'historique. Widget Flutter : Column([GroupJoinBanner?, Expanded(ListView)]) dans chat_detail_screen.

Pas de modal. Marc peut lire l'historique et décider quand il veut — la bannière reste affichée tant qu'il n'a pas choisi.

Liste vs fil. La conversation apparaît dans la liste dès l'ajout (comportement actuel). Masquer avant consentement = statut pending serveur, hors scope.
