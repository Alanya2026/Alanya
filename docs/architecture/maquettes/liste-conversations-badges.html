Les badges de compte, en situation

Cinq rendus dérivés de deux valeurs seulement. Le glyphe dit quoi, le contenant dit vérifié ou pas. Réglez la taille ci-dessous pour juger la lisibilité : c'est la décision que cette maquette doit permettre de trancher.

Les cinq rendus

La colonne « taille réelle » suit le curseur. La valeur de référence est 13 px, la taille du badge à côté d'un nom dans la liste de conversations.

Règle de dérivation

officiel l'emporte toujours : un compte officiel porte son sceau quel que soit son état de vérification. Sinon, le glyphe vient du genre (business → panier, personnel → coche) et le sceau festonné n'apparaît que si verification_status = 2. Un compte personnel non vérifié n'a aucun badge — c'est le cas courant.

Le feston à douze lobes n'est pas décoratif : un disque plein se confondrait avec les avatars, les puces de comptage et l'indicateur de présence. La silhouette reste reconnaissable même quand le glyphe qu'elle contient ne l'est plus — et elle est bien plus difficile à imiter avec un caractère Unicode dans un nom.

Conversation officielle — lecture seule

Le badge suit le nom, jamais l'avatar. Placé sur la photo, il se confondrait avec l'indicateur de présence, qui occupe déjà le coin inférieur droit — visible ici sur les deux premières lignes.

Masquer la saisie ne suffit pas. Le bandeau est une affaire d'affichage ; le refus doit aussi être appliqué par le serveur, sans quoi un client modifié enverra le message quand même.
